# سكربتات الصيانة

هذه الصفحة تصنف سكربتات `scripts/` حتى لا تختلط على المطور مع مسار التطبيق اليومي.

## القاعدة العامة

- التطبيق لا يعتمد على سكربتات الصيانة أثناء استخدام العميل.
- أي سكربت يعدل قاعدة البيانات أو ملفات الإنتاج يجب تشغيله يدويًا فقط وبعد أخذ نسخة احتياطية.
- أي سكربت يحتوي `repair`, `cleanup`, `reset`, أو `migrate` ليس جزءًا من deploy عادي إلا إذا ذكر runbook ذلك صراحة.
- GitHub يبقى مصدر الحقيقة للكود. السكربتات لا تنشئ مسار نشر بديل غير موثق.

## مسار البناء والنشر

| النوع | أمثلة | الاستخدام |
| --- | --- | --- |
| build/package | `package-production-artifact.mjs` | إنشاء artifact مطابق للـ commit الحالي |
| deploy helper | `vps_deploy.py` | رفع artifact وتشغيل خطوات النشر الموثقة |
| preflight/check | `check-clean-surface.mjs`, `verify-support-whatsapp-build.mjs` | إيقاف الأخطاء قبل النشر |

## التشخيص والقياس

| النوع | أمثلة | الاستخدام |
| --- | --- | --- |
| diagnose | `diagnose-*`, `repro-*` | إعادة إنتاج مشكلة محددة أو قراءة حالة البيئة |
| benchmark | `benchmark-*` | قياس أداء استعلام أو مسار محدد |
| inventory | `vps-readonly-*` | قراءة حالة السيرفر دون تعديل |

## الهجرة والإصلاح

| النوع | أمثلة | الاستخدام |
| --- | --- | --- |
| migrate | `migrate-*` | نقل بيانات من شكل قديم إلى الشكل الحالي |
| repair | `repair-*` | إصلاح بيانات إنتاجية محددة بعد تشخيص السبب |
| cleanup | `cleanup-*` | إزالة بقايا بيانات أو ملفات بعد تحقق يدوي |
| seed/reset | `seed-*`, `reset-*` | staging أو بيئة محلية فقط، وليس production إلا بموافقة صريحة |

## بوابة التشغيل

قبل تشغيل أي سكربت صيانة مؤثر:

1. حدد البيئة: local أو staging أو production.
2. خذ backup إذا كان السكربت يكتب.
3. شغل dry-run إذا كان متاحًا.
4. وثق الأمر والنتيجة في runbook أو خطة التحول عند ارتباطه بمرحلة ترحيل.
5. شغل الاختبارات أو smoke gate المناسب بعد التنفيذ.
