# خطة التحول 01

> آخر تحديث: 2026-06-26
> هذه الوثيقة سجل تنفيذ لخطة التحول، وليست مرجع التشغيل اليومي. المرجع اليومي هو `docs/README.md` والوثائق المعتمدة المذكورة فيه.

## الهدف

تحويل تطبيق تقفيلة إلى بنية إنتاجية واضحة:

```text
Production = Server/API/Database only
Frontend = input/display only
No operational or financial fallback in production
```

## سبب الخطة

قبل التحول كان التطبيق يحمل أسماء ومسارات تاريخية من مرحلة مبكرة، وكان بعض السلوك يسمح بمصادر بيانات محلية أو مزدوجة. هذا كان يسبب:

- احتمال اختلاف أرقام السجل والرئيسية والتقارير.
- ارتباك المبرمجين بسبب أسماء تاريخية.
- خطر ظهور بيانات قديمة أو fallback محلي في الإنتاج.
- صعوبة معرفة مصدر الحقيقة عند فحص مشكلة.

## شرط الانتقال بين المراحل

لا يتم الانتقال من مرحلة إلى التي بعدها إلا بعد إكمال المرحلة الحالية 100%، مع تحقق واضح:

- كود منفذ.
- اختبار أو حراسة مناسبة.
- توثيق محدث عند الحاجة.
- `typecheck`, `lint`, `test`, `build` ناجحة عند إغلاق المرحلة.

## المرحلة 1 — مصدر بيانات الإنتاج

الحالة: مكتملة.

تم:

- منع keep previous data المضلل في السجل والتقارير والرئيسية.
- منع fallback مالي محلي عندما تكون بيانات السيرفر مطلوبة.
- منع مرفقات الرئيسية من استخدام local fallback عند API mode.
- منع التصدير والمشاركة من استخدام local fallback عندما تكون بيانات الخادم مطلوبة.
- إضافة حراسة تمنع رجوع مصادر بيانات غير إنتاجية إلى مسار `/app`.

التحقق:

- targeted tests ناجحة.
- typecheck ناجح.
- lint ناجح.
- build ناجح.

## المرحلة 2 — فصل مدخل التطبيق الحقيقي

الحالة: مكتملة.

تم:

- فصل مدخل `/app` باسم واضح: Taqfeelah App.
- إزالة route المقارنة القديم.
- حذف loader/hook القديمين للتشغيل التاريخي.
- تثبيت أن `/app` هو مسار التطبيق التشغيلي الوحيد.

## المرحلة 3 — تنظيم مصدر السجل والتقارير

الحالة: مكتملة.

تم:

- توحيد قراءة السجل والتقارير حول API/DB في الإنتاج.
- تحسين pagination للسجل.
- منع الحساب المحلي من أن يكون مصدر الحقيقة في الإنتاج.
- إصلاح تبويبة تقرير عام عند فلتر الكل.
- تثبيت سلوك التصدير حسب الفلتر المحدد.

## المرحلة 4 — إعدادات المالك والمحلات والموظفين

الحالة: مكتملة.

تم:

- إصلاح حفظ المحلات والموظفين بعد تسجيل الخروج والدخول.
- ربط القراءة والكتابة بمصدر السيرفر.
- ضبط طريقة إدخال التقفيلة للمالك لتشمل الداخل والخارج.
- تثبيت اسم نسخة المرحلة.
- نشر staging سابقًا للتحقق اليدوي، ثم تنظيف لاحق بدون نشر.

## مرحلة التنظيف

الحالة: مكتملة محليًا، غير منشورة.

تم:

- إزالة أسماء ومسارات غير إنتاجية من الكود النشط.
- تحويل `APP_MODE` إلى `local | production`.
- إعادة تسمية ملفات seed/catalog التي كانت تحمل أسماء مربكة.
- أرشفة الوثائق التاريخية داخل `docs/archive/`.
- إعادة كتابة الوثائق النشطة المشوهة أو المتناقضة.
- إصلاح نص عربي مشوه في معاينة التسويق.

## الوضع الحالي

الكود النشط:

- لا يستخدم مسار تشغيل بديل لـ `/app`.
- لا يعتمد على fallback تشغيلي أو مالي في الإنتاج.
- لا يحتوي على أسماء ملفات نشطة مربكة من المرحلة القديمة.
- يستخدم `docs/archive/` كسجل تاريخي فقط.

الوثائق:

- `docs/README.md` هو فهرس الوثائق المعتمدة.
- الوثائق التاريخية لا تستخدم كمرجع تنفيذ.
- هذه الخطة تسجل ما أزيل ولماذا.

## خارج النطاق الآن

- Object Storage خارجي للمرفقات.
- Redis إلزامي.
- بوابة دفع فعلية.
- جداول rollup إضافية قبل قياس حقيقي.
- خطة backup/restore موثقة قبل التوسع التجاري الكبير.

## بوابة الإغلاق

قبل رفع أو نشر هذا التنظيف:

```bash
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm test
corepack pnpm build
```

ثم نشر staging فقط بعد أمر صريح.
