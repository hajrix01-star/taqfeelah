# تقفيلة — حالة المنتج وقرارات الإطلاق

> آخر تحديث: **2026-06-22**
> التطبيق منشور في بيئة staging معزولة. لا يُعتمد إطلاق الإنتاج من هذا المستند وحده؛ يلزم قرار المالك وبوابة الإطلاق.

## الملخص التنفيذي

| المحور | الحالة |
|---|---|
| التطبيق التشغيلي `/app` | منفذ ومربوط بـ PostgreSQL في وضع الإنتاج |
| المصادقة | جلسات حقيقية؛ لا دخول تجريبي في الإنتاج |
| المالك والموظف | دخول وصلاحيات وتحقق من الوصول إلى المتاجر |
| العمليات والتقفيلات | CRUD تشغيلي، تقارير، void/restore وتدقيق |
| لوحة SaaS | حسابات ومتاجر وأعضاء وخطط ومؤشرات |
| المركزية | PostgreSQL/API مصدر الحقيقة؛ تخزين المتصفح محجوب إنتاجيًا |
| الاختبارات | وحدة + تكامل PostgreSQL + Playwright + بناء CI |
| النشر | staging معزول؛ الإنتاج من `main` فقط |

## المنجز

- العمليات والتقفيلات والتقارير من PostgreSQL.
- pagination بالسجل والتقفيلات.
- إعداد المنشأة والمتاجر والموظفين والقنوات والبنود.
- مصادقة المالك والموظف واستعادة كلمة المرور.
- لوحة SaaS وإدارة الحسابات والاشتراكات الأساسية.
- معاملات قاعدة بيانات وسجل تدقيق للعمليات الحساسة.
- خطوط محلية داخل التطبيق دون اعتماد وقت التشغيل على Google.
- إزالة وضع الدخول التجريبي ومسار تجاوزه من الإنتاج.
- منع حفظ بيانات العمل وبيانات الدخول في تخزين المتصفح إنتاجيًا.
- CI يشمل typecheck واختبارات وبناء وتكامل PostgreSQL.

- ✅ حذف التقفيلة أصبح إلغاءً منطقيًا يحفظ العمليات والمرفقات والتدقيق.
- ✅ migration `0021_data_integrity_hardening` يفرض الأنواع والحالات والمبالغ والعملات الصحيحة.
- ✅ علاقات مركبة تمنع الربط العابر بين منشأة/متجر مختلفين.
- ✅ قفل PostgreSQL داخل transaction يمنع تعارض `daySequence` عند الإرسال المتزامن.

5. ✅ فصل طبقة اتصال سجل المالك عن العرض، وفصل معرض مرفقات اليوم عن الصفحة الرئيسية، مع تغطية حدود الاستيراد في smoke tests.

## مؤجل بقرار المالك

| البند | توقيته | البديل الحالي |
|---|---|---|
| Object Storage/CDN للمرفقات | بعد الإطلاق وعند التوسع | ملفات محلية معزولة على VPS + metadata في PostgreSQL |
| Redis إلزامي | عند تعدد نسخ التطبيق أو ارتفاع ضغط الدخول | memory limiter لنسخة واحدة؛ Upstash اختياري |
| الدفع الإلكتروني | لاحقًا | إدارة الاشتراك/التواصل اليدوي |
| جداول تجميع تقارير | بعد قياس بطء حقيقي | SQL aggregation مفهرس |
| النسخ الاحتياطي واختبار الاستعادة | آخر مرحلة حسب ترتيب المالك | لا يُعد مغلقًا حتى تنفذ تجربة استعادة موثقة |

التأجيل قرار نطاق، وليس ادعاء أن البند منفذ.

## المرفقات — القرار الحالي

- لا تُنقل إلى مزود خارجي في المرحلة الحالية.
- الإنتاج يستخدم `ATTACHMENT_STORAGE_MODE=local` وجذرًا خاصًا بتقفيلة.
- قاعدة البيانات تحفظ `storageKey` والاسم والنوع والحجم.
- inline يبقى للتوافق والاختبارات ويجب ألا يصبح مسار التوسع.
- يعاد تقييم Object Storage بعد الإطلاق وفق حجم الملفات، معدل النمو، والحاجة لتشغيل أكثر من خادم.

## شروط بيئة الإنتاج

- `APP_MODE=production` و`NEXT_PUBLIC_APP_MODE=production`.
- API flags الأساسية مفعلة.
- `NEXT_PUBLIC_DISABLE_BROWSER_PERSISTENCE=true`.
- `ALLOW_HEADER_AUTH_CONTEXT=false`.
- `AUTH_SESSION_SECRET` قوي ومحفوظ في GitHub Secrets.
- قاعدة الإنتاج تستخدم migrations فقط، بلا demo seed/reset.
- حساب مسؤول المنصة محدد صراحة.

راجع `.env.example` و`docs/DATA_SOURCE_UNIFICATION.md` للعقد الكامل.

## بوابة كل دفعة

```bash
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
```

وللتغييرات المؤثرة على البيانات:

```bash
corepack pnpm smoke:browser:db
corepack pnpm check:db-source
```

بعد النشر على staging:

1. تحقق من `/api/v1/meta` ورقم commit.
2. اختبر دخول المالك والموظف.
3. اختبر تقفيلة وعملية وتقريرًا وإلغاء/استعادة.
4. تحقق أن روابط الإنتاج والتطبيقات الأخرى سليمة.

## تعريف الجاهزية

- **جاهز لتجربة محدودة:** الفحوصات الآلية ناجحة والاختبار اليدوي على staging ناجح.
- **جاهز لإطلاق نهائي:** بنود P0 مغلقة، بوابة الإطلاق ناجحة، والمالك أعطى موافقة صريحة.
- **جاهز لتوسع كبير:** نتائج الضغط مقبولة، والمراقبة وRedis والتخزين المناسب منفذة حسب حجم التشغيل.
