# حالة الإنتاج

> آخر تحديث: 2026-06-26

هذه الوثيقة تلخص الوضع الحالي والقرارات المؤجلة. لا يعتمد إطلاق الإنتاج من هذه الوثيقة وحدها؛ يلزم قرار صريح من المالك وبوابة نشر ناجحة.

## الملخص

| المحور | الحالة |
|---|---|
| `/app` | منفذ ومربوط بمصدر DB/API في وضع الإنتاج |
| Auth | جلسات حقيقية، ولا يوجد دخول تجريبي في الإنتاج |
| المالك والموظف | دخول وصلاحيات وربط بالمحلات |
| العمليات والتقفيلات | إنشاء وتعديل وإلغاء منطقي وتقارير |
| SaaS Admin | إدارة حسابات ومحلات وأعضاء وخطط |
| مصدر البيانات | PostgreSQL/API هو مصدر الحقيقة |
| التخزين المحلي | ممنوع لبيانات الأعمال في الإنتاج |
| النشر | staging معزول، والإنتاج من `main` فقط |

## المنجز

- العمليات والتقفيلات والتقارير من PostgreSQL.
- pagination للسجل والتقفيلات.
- إعداد المنظمة والمحلات والموظفين والقنوات.
- مصادقة المالك والموظف واستعادة كلمة المرور.
- لوحة SaaS Admin الأساسية.
- سجل تدقيق للعمليات الحساسة.
- منع حفظ بيانات الأعمال أو بيانات الدخول في المتصفح إنتاجيًا.
- CI يشمل typecheck وtests وlint وbuild.

## سلامة البيانات

- تعديل التقفيلة يحفظ النسخة السابقة كعمليات `voided`.
- حذف التقفيلة إلغاء منطقي، لا حذف فعلي.
- قيود قاعدة البيانات تمنع ربط بيانات بين منظمات أو محلات مختلفة.
- `daySequence` يحجز داخل transaction لمنع تعارض التقفيلات المتزامنة.

## مؤجل بقرار نطاق

| البند | التوقيت | البديل الحالي |
|---|---|---|
| Object Storage خارجي | بعد الإطلاق وعند الحاجة | تخزين محلي معزول على VPS |
| Redis إلزامي | عند تعدد النسخ أو ضغط دخول عال | limiter داخل الذاكرة |
| الدفع الإلكتروني | لاحقًا | إدارة اشتراك وتواصل يدوي |
| rollup tables | بعد قياس بطء حقيقي | SQL aggregation مفهرس |
| اختبار استعادة backup | قبل توسع جاد | مطلوب توثيقه لاحقًا |

## شروط الإنتاج

- `APP_MODE=production`
- `NEXT_PUBLIC_APP_MODE=production`
- API flags الأساسية مفعلة.
- `NEXT_PUBLIC_DISABLE_BROWSER_PERSISTENCE=true`
- `ALLOW_HEADER_AUTH_CONTEXT=false`
- `AUTH_SESSION_SECRET` قوي ومحفوظ في secrets.
- الإنتاج يستخدم migrations فقط.
- لا seed أو reset على الإنتاج.

## بوابة كل دفعة

```bash
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
```

بعد النشر على staging:

1. تحقق من `/api/v1/meta`.
2. اختبر دخول المالك والموظف.
3. اختبر تقفيلة وعملية وتقريرًا.
4. اختبر إلغاء/استعادة.
5. تحقق أن الإنتاج لم يتأثر.

## تعريف الجاهزية

- جاهز لتجربة محدودة: الفحوصات الآلية ناجحة واختبار staging اليدوي ناجح.
- جاهز للايف: بوابة الإطلاق ناجحة والمالك وافق صراحة.
- جاهز لتوسع كبير: قياسات الضغط والمراقبة والتخزين مناسبة لحجم التشغيل.
