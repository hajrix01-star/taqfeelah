## ملخص سريع

| السؤال | الجواب |
|--------|--------|
| هل التطبيق التشغيلي يعمل على الإنتاج؟ | **نعم** — تقفيلات، عمليات، تقارير، إعدادات، دخول حقيقي |
| هل منصة SaaS مفعّلة؟ | **نعم** على النشر الحالي (`DEPLOYMENT_WAVE=7`) عند ضبط الأسرار |
| هل المنتج «كامل 100%»؟ | **لا** — بندان مؤجّلان بقرار صريح + بنود تشغيلية اختيارية |

## مؤجّل بقرار المالك (خارج النطاق الحالي)

| البند | السبب | البديل الحالي |
|-------|--------|----------------|
| **الدفع الإلكتروني** (Stripe/Moyasar/checkout) | مؤجّل | ترقية الاشتراك عبر واتساب الدعم |

## يحتاج إجراء تشغيلي (ليس نقص كود)

| البند | الإجراء |
|-------|---------|
| `AUTH_SESSION_SECRET` على VPS | يجب أن يأتي من سر GitHub — لا الاعتماد على bootstrap الافتراضي |
| `SAAS_PLATFORM_ADMIN_USER_IDS` | UUID مالك المنصة في أسرار GitHub |
| migration `0011_trial_plan_catalog` | يُطبَّق تلقائيًا عند النشر (`drizzle-kit migrate`) |
| `pnpm saas:aggregate` | اختياري — cron يومي لملء مقاييس engagement |
| `USAGE_TRACKING_ENABLED` | اختياري — `false` افتراضيًا |
| استعادة كلمة المرور بالبريد | يحتاج `RESEND_API_KEY` أو SMTP — أو الاعتماد على رابط الإعداد اليدوي |
| تسجيل ذاتي عام (signup عام) | **غير مخطط** — الحسابات تُنشأ من لوحة المنصة |

## خرائط المعرفات (ID maps)

| الوضع | متطلب env maps |
|-------|----------------|
| `PROTOTYPE_ACCESS_MODE=true` أو `ALLOW_HEADER_AUTH_CONTEXT=true` | **مطلوبة** (`STORE/USER/CHANNEL_ID_MAP`) |
| Auth launch كامل (`false` لكليهما + auth flags) | **اختيارية** — الجلسة + org-config API يكفيان |

المنشآت الجديدة عبر SaaS Admin لا تحتاج maps في البيئة.

---

## شفافية: ما ليس 100%

1. **الدفع** — تقدير MRR/ARR في لوحة المستثمر فقط، لا تحصيل فعلي.
2. **المرفقات** — لا تخزين سحابي منفصل بعد.
3. **OTP/واتساب للدخول** — معطّل (`AUTH_OTP_ENABLED` off).
4. **بريد تلقائي** لروابط الإعداد — نسخ يدوي أو واتساب من لوحة المنصة.
5. **ثيم لوحة الإدارة العاجي** — في PR #189 (يُدمج مع دفعة الإكمال).
6. **تحقق النشر** (`vps_deploy.py`) — ما زال يستخدم منشأة bootstrap ومعرّفات legacy في smoke الداخلي.
