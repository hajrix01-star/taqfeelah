# خطة SEO والتسويق قبل الإطلاق

> آخر تحديث: 2026-07-14

هذه الوثيقة هي خطة تنفيذ ومراجعة لرفع جاهزية تقفيلة في الظهور العضوي، المشاركة الاجتماعية، وتحويل الزائر إلى تجربة أو تواصل. لا يعتبر أي بند "منجزًا" إلا إذا تم تنفيذ الكود أو المحتوى، ثم تم التحقق منه بدليل واضح.

## الهدف التنفيذي

تقفيلة تطبيق SaaS تشغيلي للمحلات. الهدف قبل الإطلاق ليس فقط أن تكون الصفحة موجودة، بل أن تكون مفهومة لمحركات البحث، قابلة للمشاركة باحتراف، وتشرح القيمة للمالك خلال ثوان.

## مستهدفات الإطلاق

| المجال | الوضع الحالي | المستهدف قبل اللايف | معيار القبول |
| --- | ---: | ---: | --- |
| SEO تقني | 45/100 | 85/100 | وجود sitemap وrobots وcanonical وmetadata صحيحة |
| SEO محتوى | 55/100 | 75/100 | صفحة رئيسية برسالة واضحة ومحتوى كاف، مع خطة صفحات لاحقة |
| المشاركة الاجتماعية | 35/100 | 90/100 | Open Graph/Twitter metadata وصورة مشاركة مخصصة |
| التسويق والتحويل | 68/100 | 82/100 | عرض واضح، CTA واضح، ثقة، اعتراضات مجابة |
| أمان الفهرسة | غير مكتمل | 100/100 | منع فهرسة التطبيق ولوحات الإدارة وصفحات auth الحساسة |

## نطاق العمل

### داخل النطاق

- تحسين SEO التقني للصفحة العامة.
- إضافة أو ضبط `robots` و`sitemap`.
- إضافة Open Graph وTwitter metadata.
- إضافة canonical URL عند توفر نطاق الإنتاج.
- إضافة Schema مناسب لتقفيلة كبرنامج SaaS.
- حماية صفحات التطبيق الداخلية من الفهرسة.
- تحسين الرسالة التسويقية ومناطق التحويل في الصفحة العامة.
- توثيق ما تم وما لم يتم بعد التنفيذ.

### خارج النطاق الآن

- نشر GitHub أو production بدون أمر صريح من المالك.
- بناء مدونة كاملة أو صفحات SEO كثيرة دفعة واحدة.
- حملات إعلانية مدفوعة.
- وعود ترتيب في Google؛ المطلوب جاهزية صحيحة، وليس ضمان ترتيب.

## قائمة التحقق الفنية SEO

| البند | الأولوية | الحالة | دليل القبول |
| --- | --- | --- | --- |
| إضافة `src/app/robots.ts` | P0 | مخطط | يسمح بفهرسة `/` ويمنع `/app`, `/saas-admin`, `/auth`, `/api` |
| إضافة `src/app/sitemap.ts` | P0 | مخطط | يحتوي الصفحة الرئيسية وأي صفحات عامة فقط |
| ضبط metadata للصفحة الرئيسية | P0 | مخطط | عنوان ووصف واضحان لتقفيلة وليس فقط اسم التطبيق |
| إضافة Open Graph | P0 | مخطط | عند مشاركة الرابط تظهر صورة وعنوان ووصف احترافي |
| إضافة Twitter card | P1 | مخطط | مشاركة مناسبة للمنصات التي تستخدم Twitter metadata |
| إضافة canonical | P0 | مخطط | يستخدم نطاق الإنتاج من متغير بيئة موثق |
| إضافة Schema JSON-LD | P1 | مخطط | SoftwareApplication أو WebApplication بدون مبالغة أو بيانات وهمية |
| منع فهرسة صفحات الدخول والإدارة | P0 | مخطط | صفحات `/app` و`/saas-admin` و`/auth/*` تحمل `noindex` |
| التأكد من اللغة والاتجاه | P1 | مخطط | `html lang="ar"` وواجهة الصفحة RTL |
| مراجعة الصور والأيقونات | P1 | مخطط | أي صورة تسويقية لها أبعاد مناسبة ونص بديل عند الحاجة |

## صفحات SEO المقترحة لاحقًا

هذه ليست شرطًا للإطلاق الأول، لكنها خطة نمو بعد استقرار المنتج:

| الصفحة | الهدف | الأولوية |
| --- | --- | --- |
| `/features` | شرح الميزات بشكل قابل للفهرسة | P2 |
| `/pricing` | صفحة تسعير مستقلة | P2 |
| `/use-cases/daily-closeout` | استهداف "تقفيل يومية محل" | P2 |
| `/use-cases/store-expenses` | استهداف "مصروفات محل" | P3 |
| `/compare/accounting-vs-operations` | شرح الفرق بين المحاسبة والتشغيل | P3 |

## قواعد الجودة

- لا تتم فهرسة أي صفحة تحتوي بيانات مستخدم أو تطبيق داخلي.
- لا نضيف Schema فيه تقييمات أو أسعار أو ادعاءات غير حقيقية.
- لا نستخدم كلمات تسويقية مبالغ فيها مثل "الأفضل" بدون دليل.
- لا نفتح صفحات كثيرة بمحتوى ضعيف؛ صفحة قوية أفضل من عشر صفحات ضعيفة.
- أي رقم أو ادعاء تسويقي يجب أن يكون صحيحًا أو محذوفًا.
- أي تعديل SEO يجب ألا يكسر تسجيل الدخول أو PWA.

## اختبارات القبول

بعد التنفيذ يجب تشغيل أو تنفيذ التالي حسب المتاح:

- [ ] فحص lint.
- [ ] فحص typecheck.
- [ ] اختبار أن `/robots.txt` يعمل.
- [ ] اختبار أن `/sitemap.xml` يعمل.
- [ ] فحص HTML للصفحة الرئيسية والتأكد من وجود title/description/og/canonical.
- [ ] فحص أن `/app` يحمل `noindex` أو ممنوع بوضوح من الفهرسة.
- [ ] فتح الصفحة على الجوال والتأكد من وضوح أول شاشة والزر الأساسي.
- [ ] مشاركة الرابط تجريبيًا أو فحص metadata لصورة المشاركة عند توفر نطاق.

## سجل المقارنة بعد التنفيذ

يتم تعبئة هذا القسم بعد العمل، ولا يترك بصيغة عامة.

| البند | المخطط | المنفذ فعليًا | النتيجة | الدليل |
| --- | --- | --- | --- | --- |
| robots | منع الصفحات الداخلية وفهرسة العامة | لم ينفذ بعد | غير مكتمل | - |

| منع فهرسة التطبيق | noindex للصفحات الحساسة | لم ينفذ بعد | غير مكتمل | - |
| تحسين الرسالة التسويقية | صفحة أوضح وتحويل أفضل | لم ينفذ بعد | غير مكتمل | - |
| الاختبارات | lint/typecheck وفحص يدوي | لم ينفذ بعد | غير مكتمل | - |

## قرار الجاهزية

قبل الإطلاق، القرار يكون:

- Go: كل بنود P0 مكتملة، والاختبارات الأساسية ناجحة، ولا توجد صفحة داخلية قابلة للفهرسة.
- No-Go: أي بند P0 غير مكتمل، أو وجود فهرسة محتملة للتطبيق الداخلي، أو metadata مضللة/ناقصة.
