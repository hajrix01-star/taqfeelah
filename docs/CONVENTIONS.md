# معايير مشروع تقفيلة

> آخر تحديث: 2026-06-26

هذه الوثيقة هي مرجع المطور اليومي. عند التعارض، يقدم الكود الحالي ثم هذه الوثيقة.

## نطاق المنتج

تقفيلة تطبيق تشغيل يومي للمحلات، وليس نظام محاسبة أو ERP أو POS.

المعادلة الأساسية:

```text
الداخل - الخارج = الناتج
```

يدعم التطبيق:

- تقفيلات يومية لكل محل.
- تسجيل الداخل حسب طرق الدفع وقنوات البيع.
- تسجيل الخارج كعمليات مستقلة: مشتريات، مصروف، سحب.
- السجل، التقارير، التصدير، والمرفقات.
- تعدد المحلات داخل منظمة واحدة.
- أدوار المالك والموظف.

## مصدر الحقيقة

في الإنتاج:

- DB/API هو مصدر الحقيقة.
- الجلسة الموقعة هي مصدر الهوية.
- لا بيانات أعمال دائمة من المتصفح.
- لا مصدر محلي بديل للعمليات أو التقفيلات أو المحلات أو الموظفين.
- عند فشل API أو DB، اعرض خطأ واضحًا بدل أرقام بديلة.

راجع `DATA_SOURCE_UNIFICATION.md`.

## بنية الكود

```text
src/
  app/                 routes فقط
  components/taqfeelah-app/
  core/
  domain/
  features/
```

قواعد العمل:

- `page.tsx` يستورد feature أو shell فقط.
- الحسابات المرجعية لا توضع داخل React components.
- المنطق المشترك يوضع في `core` أو `domain` أو `features` حسب الملكية.
- `/app` هو مسار التطبيق التشغيلي الوحيد.
- لا تضف أسماء demo/prototype أو مسارات تشغيل بديلة.

## العمليات

```ts
type EntryType = "summary" | "purchases" | "expense" | "withdrawal";
```

- `summary` للداخل فقط.
- الخارج يسجل كعمليات مستقلة.
- الحذف المالي يكون `void`.
- الاسترجاع يكون `restore`.
- لا حذف فعلي لعمليات تؤثر على الأرقام.

## التقفيلات

`DailyCloseout` يمثل تقفيلة يومية لمحل واحد، وتشمل الداخل والخارج والمرفقات وسجل التدقيق.

السياسة الحالية:

- إرسال الموظف يعتمد فورًا في DB.
- تعديل المالك أو المدير لتقفيلة مرسلة يتم عبر `ownerEdit`.
- النسخة السابقة تصبح `voided` ولا تحذف فعليًا.

## المصادقة

في الإنتاج:

- دخول حقيقي فقط.
- جلسات موقعة.
- لا role picker.
- لا PIN أو OTP ثابت داخل الكود.
- لا أسرار داخل Git.

## تعريف "منجز"

الميزة منجزة عندما تكون:

- مربوطة بمصدر بيانات صحيح.
- محمية بالصلاحيات.
- لا تستخدم مصدرًا محليًا بديلًا في الإنتاج.
- قابلة للاختبار.
- موثقة عند الحاجة.

بوابة التحقق المعتادة:

```bash
pnpm check:clean-surface
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```
